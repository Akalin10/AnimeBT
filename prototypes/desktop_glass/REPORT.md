# 桌面级 Liquid Glass 原型验收报告

结论：已在本机实现真实 Windows 桌面捕获到 Qt Quick Shader 的 GPU 渲染链路，独立原型可行；尚不适合默认集成正式 AnimeBT。

## 修改范围

全部新增内容位于 `prototypes/desktop_glass/`：

- `capture.cpp`：WGC、显示器选择、自身排除、D3D11 BGRA→RGBA 转换、设备错误与 GPU 时间戳。
- `run.py`：PySide Scene Graph 纹理桥接、默认关闭、运行预算保护、输入和内存测量。
- `Prototype.qml`：实时桌面材质、透射/模糊/折射调节、阅读保护和输入测试。
- `Pattern.qml`：独立 Windows 桌面测试窗口。它不是应用内 Shader 的背景节点，图案必须先经过桌面合成与 WGC 才能进入 Shader。
- `build.py`、`verify.py`：可复现构建与独立验收。
- `README.md`、本报告：架构、使用方式和限制。
- `.gitignore`：排除 DLL、测试截图、日志及缓存。没有提交或上传任何内容。

正式 AnimeBT 的搜索、GUI、TUI、用户设置与着色器代码均未在本任务中修改。现有 100 项回归测试通过（28.261 秒）。

## 验证证据

对照截图使用同一位置的真实静止桌面图案：两个状态都关闭模糊和高光，仅改变折射强度，避免将亮度或模糊误当成几何变化。
中央 RGB 平均绝对差：1.928；边缘：19.872。均非零，边缘响应更强。数值用于证明画面位移，不用于宣称物理光学精度。

| 场景 | 实际结果 |
| --- | --- |
| 普通启动 | 捕获帧数 0，未建立 WGC，会显示现有应用内材质 |
| 深浅色 | 实际渲染，桌面文字与条纹随背景更新；中央透射、局部边缘弯曲可见 |
| 移动/缩放 | 920×590 调整到 1000×650，重新计算物理客户区采样 |
| 150% DPI | 逻辑 920×590 对应物理 1380×885；使用 QT_SCALE_FACTOR 测试，未修改系统设置 |
| 双显示器 | 从 1920×1080 切换至 1080×1920，成功重建 WGC 并返回新尺寸纹理 |
| 跨屏边界 | 主动回退应用内材质，不拼接或重复错误桌面像素 |
| 停止 / 重新开启 | 关闭帧池与会话，恢复捕获可见性；再次开启成功 |
| 权限拒绝 | 模拟 E_ACCESSDENIED，回退成功；没有改变 OS 权限策略 |
| 设备丢失 | 模拟 DXGI_ERROR_DEVICE_REMOVED，回退成功；未重置真实显卡 |

## 性能测量

本机有 Intel UHD 与 NVIDIA RTX 4060 Laptop GPU，Qt 使用 D3D11。以下是短时实验，不是跨设备保证。
| 指标 | 实测 |
| --- | ---: |
| Qt frameSwapped 提交事件 / 秒 | 67.42 |
| 实际新桌面帧导入 / 秒 | 46.89 |
| Qt 提交间隔 P95 | 21.761 ms |
| GPU 复制 + 转换中位数 / P95 | 0.052 / 0.055 ms |
| 桌面帧时间戳到导入中位数 / P95 | 5.446 / 13.543 ms |
| QML 鼠标按压事件到下一次场景更新中位数 / P95 | 5.198 / 15.813 ms |
| 原型进程 3D 引擎利用率（独立 22 秒测试的四次采样） | 4, 4, 5, 4 % |
| 工作集峰值 / 私有提交峰值 | 146 / 199.6 MiB |
| DXGI 本进程本地视频内存峰值 | 96.5 MiB |

测量口径与限制：

- frameSwapped 统计 Qt 提交，不是显示器扫描帧率；鼠标事件也可触发额外提交。新桌面帧导入约 47Hz，不能冒充 60Hz 的全新捕获内容。
- GPU 时间戳只覆盖复制与格式转换，不包括整个 WGC 系统服务或全部 QML 光学渲染。GPU 引擎计数器包含原型和同进程动态测试图案，不是整机利用率，也不能对多个引擎百分比直接相加。
- 输入用 QTest 真实投递鼠标事件，时间从 QML pressed 到后续 Scene Graph 更新；没有光电设备，因此不能给出物理输入到屏幕发光延迟。
- 包含启动、移动、重新开启与证明图读回的测量有超过 100ms 的偶发长帧；不宣称全程锁定 60FPS。无截图短测同样存在初始化长帧。
- 另完成 32 秒持续运行，采集 1441 帧；工作集后段约 141MiB。本次未做小时级泄漏或电池续航测试。
- 普通逐帧路径不经过 CPU 像素上传；受控诊断单次读取一个像素，显式保存证明图也涉及有限次读回。这些不能算成零读回测试。

## 尚存限制与集成门槛

1. 自身排除会影响其他截图、录屏与共享；不能同时默认保证自我排除和正常被所有软件录制。当前只验证系统亲和性设置与自身不递归，没有逐个测试 OBS、会议软件和其他抓屏方式。
2. Qt 原生纹理接口尚无 PySide 绑定。当前桥接限定 Qt 6.12.0、Windows x64，并使用 basic render loop。正式集成应替换为同版本 Qt SDK 构建的 C++ QML 模块；不应去掉版本检查直接发布。
3. 当前每帧存在一次 GPU 复制及一次格式转换，不是零复制。没有持续 GPU→CPU→GPU 往返，也没有每帧全屏 CPU 截图。
4. 单显示器捕获可以跨显示器重建；跨屏拼接未实现，跨屏窗口主动回退。不同显卡上的显示器、HDR、VRR、热插拔、锁屏与真实显卡丢失尚未验收。
5. 读取桌面内容在隐私上不同于普通材质。默认关闭、保留系统捕获提示、不上传内容；正式集成还需合适的授权入口与选择显示器交互。
6. 透明测试区域故意让背景文字可见，以证明真实采样；正式 GUI 的资源标题阅读区域仍需单独验证对比度与背景抑制，不能把原型样式直接全局套用。

架构与官方接口依据见 [README](README.md)。当前结论是“GPU 桌面折射原型可行”，不是“已完成生产集成”。
